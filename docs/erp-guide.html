ERP & Business Dashboard

One system for party records, the yarn/fabric ledger, transactions, employees & attendance, and CSV reports — with each of five roles seeing only what their job needs. This page is the one to hand someone before they log in.

Parties — live Yarn & Fabric Ledger — live Transactions — live Employees & Attendance — live Users & Roles — live Reports (CSV) — live

What it is

A shared record of every party you deal with — like MAGNUS — and every movement against their yarn/fabric account: yarn received, yarn returned, fabric dispatched, with the 2% process-loss allowance and running balance computed automatically, plus general payments and receivables.

Instead of one spreadsheet per person, everyone works from the same live list. Who can only look, and who can add or change something, depends on the role they log in with — enforced by the server itself, not just hidden buttons.

Procedure

Adding a yarn/fabric ledger entry

  1. Open the party's page

    From Parties, click the party name — e.g. MAGNUS.

  2. Click Add Entry in the Yarn & Fabric Ledger panel

    Visible to Admin, Manager, and Finance.

  3. Pick the movement type

    Yarn Received or Yarn Returned ask for bags and kg. Fabric Dispatched asks for kg and a knitting rate (PKR/kg) instead — the 2% loss and billed amount are calculated automatically as you type, never entered by hand.

  4. Submit

    The running balance, count breakdown, and date-wise reconciliation table all update immediately.

Procedure

Adding a party

  1. Sign in

    Use an Admin, Manager, or Finance login — the only roles with add access. See the credentials table below.

  2. Open Parties

    Click Parties in the top navigation.

  3. Click Add Party

    Fill in name, type (customer / vendor / both), phone, and email, then submit.

  4. Check for a duplicate warning

    If the name closely matches an existing party, a yellow notice lists the possible match. The new record is still created either way — the notice is a prompt to check, not a block.

Procedure

Adding transaction data

  1. Open the party's page

    From the Parties list, click the party name to reach its detail page.

  2. Click Add Transaction

    In the Transactions panel — visible to Admin, Manager, and Finance.

  3. Fill in the entry

    Type — receivable, payable, payment in, payment out, or adjustment — plus date, amount, and a description. For yarn/fabric movements specifically, use the Yarn & Fabric Ledger above instead — it tracks bags/kg and computes loss automatically.

  4. Submit

    The entry appears at the top of that party's ledger immediately, newest first.

Procedure

Adding an employee & marking attendance

  1. Open Employees, click Add Employee

    Admin, Manager (view only), and HR (full access) can see this. Enter name, national ID, phone, and/or email.

  2. Duplicate protection is automatic

    An exact match on national ID, email, or phone against any existing employee — active or not — is blocked outright, with a link to the existing record. A similar name with no exact match is allowed through, with a warning.

  3. Mark attendance from the employee's page

    Pick a date and status (present, absent, late, half day, leave, holiday, weekend), optionally check-in/check-out times — working hours are calculated automatically. Marking the same day again updates that day rather than creating a duplicate.

  4. Change status as needed

    Candidate → Active → Inactive/Resigned/Terminated, reversible back to Active. Nothing is ever deleted — attendance history stays intact regardless of current status.

Procedure

Creating a login & exporting reports

  1. Open Users, click Add User

    Admin only. Set a temporary password and pick a role from the dropdown — the new person must change that password the first time they sign in.

  2. Download a CSV from Reports

    Parties, Transactions, or the Yarn & Fabric Ledger — optionally filtered to one party. Visible to anyone with reports access; Finance and Admin can also re-import.

  3. Re-import a Yarn Ledger CSV

    Edit the exported file and upload it back on the same page — loss and billed amount are always recalculated from kg/rate, never taken from the file, so an edited spreadsheet can't quietly disagree with the ledger's own math.

Build status

What's working today, what isn't yet

Live now

  • Party records — add, search, deactivate
  • Yarn/fabric ledger — bags, kg, 2% loss, running balance
  • Date-wise reconciliation & yarn-count breakdown
  • Transaction ledger per party — add & view
  • Employees — add with duplicate prevention, lifecycle status
  • Attendance — per-day records, auto-computed hours
  • Users & Roles admin screen — create logins without touching a script
  • Reports — CSV export (parties/transactions/yarn ledger) & CSV re-import
  • Role-based access, enforced on the server
  • Duplicate-party warning on add
  • Dashboard totals — party & transaction counts

Not built yet

  • An audit log viewer (entries are recorded, just not browsable yet)
  • PDF export (CSV only for now)
  • Importing the original spreadsheet files directly (this ledger was entered by hand from them; CSV re-import above is a narrower working substitute)
